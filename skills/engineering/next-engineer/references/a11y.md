# Accessibility

Semantic HTML first. ARIA is a patch for cases where no native element expresses the semantics — reaching for it before checking the HTML options usually makes things worse.

---

## Semantic Structure

```tsx
// app/layout.tsx
export default function RootLayout({ children }: { children: React.ReactNode }) {
  return (
    <html lang="en">
      <body>
        <a href="#main" className="sr-only focus:not-sr-only focus:absolute focus:z-50 focus:p-4">
          Skip to content
        </a>
        <header>
          <nav aria-label="Main">…</nav>
        </header>
        <main id="main">{children}</main>
        <footer>…</footer>
      </body>
    </html>
  )
}
```

- `lang` on `<html>` — screen readers pick pronunciation from it.
- Exactly one `<main>` per page.
- Landmark elements (`header`, `nav`, `main`, `aside`, `footer`) give jump targets. Multiple `<nav>`s each need a distinguishing `aria-label`.
- A skip link is the first focusable element, visually hidden until focused.

Headings descend without gaps: one `<h1>`, then `<h2>`, then `<h3>`. Never pick a heading level for its font size — style it instead.

## Focus Across Navigation

Client-side navigation does not move focus the way a full page load does. Next.js moves focus to the new page's root on route change, but a route that renders inside a `<Suspense>` boundary or a modal needs help.

```tsx
'use client'
import { useEffect, useRef } from 'react'
import { usePathname } from 'next/navigation'

export function FocusOnRouteChange() {
  const pathname = usePathname()
  const ref = useRef<HTMLDivElement>(null)
  useEffect(() => { ref.current?.focus() }, [pathname])
  return <div ref={ref} tabIndex={-1} className="outline-none" aria-live="polite" />
}
```

`tabIndex={-1}` makes an element programmatically focusable without adding it to tab order.

## Focus Trapping in Dialogs

```tsx
'use client'
import { useEffect, useRef } from 'react'

export function Modal({ open, onClose, title, children }: ModalProps) {
  const dialogRef = useRef<HTMLDivElement>(null)
  const previouslyFocused = useRef<HTMLElement | null>(null)

  useEffect(() => {
    if (!open) return
    previouslyFocused.current = document.activeElement as HTMLElement
    dialogRef.current?.focus()

    function onKeyDown(e: KeyboardEvent) {
      if (e.key === 'Escape') onClose()
      if (e.key !== 'Tab') return

      const focusables = dialogRef.current?.querySelectorAll<HTMLElement>(
        'a[href], button:not([disabled]), input:not([disabled]), select, textarea, [tabindex]:not([tabindex="-1"])'
      )
      if (!focusables?.length) return
      const first = focusables[0]
      const last = focusables[focusables.length - 1]

      if (e.shiftKey && document.activeElement === first) { e.preventDefault(); last.focus() }
      else if (!e.shiftKey && document.activeElement === last) { e.preventDefault(); first.focus() }
    }

    document.addEventListener('keydown', onKeyDown)
    return () => {
      document.removeEventListener('keydown', onKeyDown)
      previouslyFocused.current?.focus()          // restore on close
    }
  }, [open, onClose])

  if (!open) return null

  return (
    <div className="fixed inset-0 bg-black/50" onClick={onClose}>
      <div
        ref={dialogRef}
        role="dialog"
        aria-modal="true"
        aria-labelledby="modal-title"
        tabIndex={-1}
        onClick={e => e.stopPropagation()}
      >
        <h2 id="modal-title">{title}</h2>
        {children}
      </div>
    </div>
  )
}
```

Radix UI (and therefore shadcn/ui) handles all of this. Prefer it over hand-rolling — the edge cases are numerous and the failure is invisible to sighted mouse users.

## Announcing Async Changes

Screen readers do not notice DOM updates unless told.

```tsx
// Status region — announced without stealing focus
<div role="status" aria-live="polite" className="sr-only">
  {pending ? 'Saving…' : saved ? 'Saved' : ''}
</div>

// Errors — assertive interrupts
<p role="alert" aria-live="assertive">{error}</p>
```

The live region must be in the DOM **before** the message appears. Mounting the region and its text at once often goes unannounced — render an empty region and fill it.

Under streaming, wrap the boundary so the arrival of content is announced:

```tsx
<Suspense fallback={<div role="status" aria-live="polite">Loading results…</div>}>
  <SearchResults query={q} />
</Suspense>
```

## Forms

```tsx
<div>
  <label htmlFor="email">Email address</label>
  <input
    id="email"
    name="email"
    type="email"
    autoComplete="email"
    required
    aria-invalid={!!errors.email}
    aria-describedby={errors.email ? 'email-error' : 'email-hint'}
  />
  <p id="email-hint">We only use this for order updates.</p>
  {errors.email && <p id="email-error" role="alert">{errors.email}</p>}
</div>
```

- A visible `<label htmlFor>` for every input. Placeholders disappear on typing and fail contrast.
- `autoComplete` tokens help everyone, and materially so for motor and cognitive impairments.
- Radio and checkbox groups go in `<fieldset>` with `<legend>`.
- Move focus to the first invalid field after a failed submit.

See `references/forms-patterns.md`.

## Images

```tsx
import Image from 'next/image'

<Image src={product.imageUrl} alt={`${product.name} — ${product.color}`} width={400} height={300} />

<Image src="/divider.svg" alt="" aria-hidden width={800} height={2} />   {/* decorative */}
```

`alt=""` (empty, not missing) marks an image decorative. A missing `alt` makes screen readers read the filename.

Alt text describes purpose, not appearance. For a link-wrapped image, the alt is the link text — describe the destination.

## Interactive Elements

```tsx
// ❌ Not focusable, not keyboard-operable, not announced as a control
<div onClick={handleClick}>Delete</div>

// ✅
<button type="button" onClick={handleClick}>Delete</button>

// Icon-only button needs a name
<button type="button" onClick={onClose} aria-label="Close dialog">
  <XIcon aria-hidden />
</button>
```

`<button>` vs `<a>`: an action is a button, a destination is a link. `<Link>` renders an anchor — do not use it for actions.

Never remove focus outlines without a replacement:

```css
/* ❌ */ :focus { outline: none; }
/* ✅ */ :focus-visible { outline: 2px solid var(--color-focus); outline-offset: 2px; }
```

## Motion

```css
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after {
    animation-duration: 0.01ms !important;
    animation-iteration-count: 1 !important;
    transition-duration: 0.01ms !important;
    scroll-behavior: auto !important;
  }
}
```

Next 16 removed the automatic `scroll-behavior: smooth`. Opt back in with `data-scroll-behavior="smooth"` on the document — and still respect the reduced-motion query.

React 19 View Transitions should also be gated on the preference.

## Testing

```tsx
import { render } from '@testing-library/react'
import { axe, toHaveNoViolations } from 'jest-axe'
expect.extend(toHaveNoViolations)

it('has no accessibility violations', async () => {
  const { container } = render(<ProductCard product={mockProduct} />)
  expect(await axe(container)).toHaveNoViolations()
})
```

```ts
// e2e/a11y.spec.ts
import AxeBuilder from '@axe-core/playwright'

test('checkout page is accessible', async ({ page }) => {
  await page.goto('/checkout')
  const results = await new AxeBuilder({ page })
    .withTags(['wcag2a', 'wcag2aa', 'wcag21aa'])
    .analyze()
  expect(results.violations).toEqual([])
})
```

Automated tools catch roughly a third of real issues. The rest needs manual checks:

- Tab through the whole page. Is focus always visible, and is the order sensible?
- Operate every control with keyboard only.
- Zoom to 200%. Does anything clip or overlap?
- Run a screen reader over one critical flow (VoiceOver: `Cmd+F5`).

Prefer RTL queries that mirror how users find things: `getByRole`, `getByLabelText`, `getByText`. `getByTestId` is a last resort — a component that cannot be found by role usually has an accessibility problem.

## Common Failure Modes

| Symptom | Cause |
|---|---|
| Screen reader silent on route change | Focus not moved; no live region |
| Modal reachable behind the overlay | No focus trap, no `aria-modal` |
| Icon button announced as "button" | Missing `aria-label` |
| Filename read instead of description | Missing `alt` (use `alt=""` for decorative) |
| Focus invisible | `outline: none` without a `:focus-visible` replacement |
| Errors not announced | No `role="alert"`, or the region mounted with its text |
| Contrast failures in dark mode | Tokens redefined without re-checking ratios |
| Keyboard users cannot activate a control | `<div onClick>` instead of `<button>` |
